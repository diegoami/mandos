# Mandos: verified bug-fix consumer

Owner direction recorded in [181](https://github.com/diegoami/mandos/issues/181),
coordinated with [runtime180](https://github.com/diegoami/mandos/issues/180) and
[workspace22](https://github.com/diegoami/angband-workspace/issues/22).
This supersedes old experimental roadmaps as the current Mandos purpose.
The C-only tracking refinement in [203](https://github.com/diegoami/mandos/issues/203)
and [the milestone contract](C-MILESTONE-ADOPTION.md) replaces per-source mirrors;
it changes no gameplay or parked-work authorization.

## Active work

1. Read current canonical bug/source state and incoming delivered corrections.
2. Reproduce a specific defect with legal public-API inputs and negative controls.
   Fixed seeds are useful regression fixtures, not a mandate for broad cohorts.
3. Apply the smallest applicable correction with provenance and a removal unit.
   Port/Neo engine/C source repairs stay with their source owners. C intake is
   a reviewed immutable better-borg-c milestone after port-gate clearance, with
   independent TS applicability/proof. Do not open per-source Mandos C mirrors;
   the faithful port is not a C-correction translation service.
4. Verify the supported package/plugin and affected basic gameplay path. Keep
   targeted regressions and basic run/death/stall/archive evidence. Do not infer
   success from emitted commands or treat counters as measured survival benefit.
5. Engine/port carries retain their upstream-resolution/adoption lifecycle.
   C milestone work closes ADOPTED after all applicable coverage is verified,
   not source fixed. Per-unit TS retirement requires its actual Neo replacement
   and controls; native patch removal alone is insufficient. No milestone code
   starts while the classified port-first gate has a real missing parity leaf.

Prefer an unpatched published engine. An engine carry requires evidence that a
real supported Mandos gameplay path needs it, a focused regression and a named
removal condition. Generic engine defects remain source-owned even when no
Mandos carry is necessary. Runtime180 has selected unpatched beta.3 for the
Core/harness after actual raw/carry controller and basic-run equivalence checks,
plus C/class controls. This does not establish interactive stock-host support
or deploy the old lab; final package/plugin adoption checks stay explicit.
PR433/seed-birth recording is not a mandatory default dependency. Preserve its
optional patch and historical profile, without pretending missing metadata exists.

The nine existing verified TS corrections and their controls/provenance/removal
units remain intact. [The ledger](../patches/c-translations/README.md) links eight
to reviewed native units, not a completed milestone audit. Enlightenment remains
a grandfathered verified unit; native157's later adoption remains outside the
reviewed M3 target. The21 old C-source
mirrors are superseded tracking history, not source-fixed or removed-code claims;
203 owns adoption coverage and the native producer owns per-bug follow-up.

## Interactive host boundary

Official beta.3 desktop/web does not register an automatic controller for the
own Mandos ID. The [official97ce shim gate at603](https://github.com/neostryder/neo-angband/blob/97ceec2925e6715ba725624a61866ab93a196a12/packages/web/src/mod-api2-shim.ts#L603)
restricts registration to first-party origins, whose compiled list lacks Mandos.
No supported configuration route was found; adding `engine:access` alone does
not make it work. The successful unpatched-Core/harness tests are a different
consumer profile, not a stock-desktop title/Ctrl-Z/autorestart recipe.

The retained authorized first-party host/lab code remains unchanged, with no
upgrade/deployment claim. Host compatibility stays a basic tracked limitation
under132/source8 and [180](https://github.com/diegoami/mandos/issues/180) /
[workspace22](https://github.com/diegoami/angband-workspace/issues/22); it does not
start a new platform implementation, host rewrite or identity substitution task.
Lab validation requires separate authorization. Ordinary bug completion checks
the affected in-scope package/plugin/harness and records the undeployed/unverified
lab boundary; it does not require a private lab deployment.

## Parked optional work

Strategy tuning/new policies, large performance or class×seed cohorts,
stage-aware home/build research, save ladders, trainer interaction, feedback
corpora and advanced per-death export/diagnosis/aggregation are parked.
Existing implementations, optional tests, saved branches and public evidence
remain available; none is silently deleted, declared complete or migrated.
In particular,166 and exporter110d682/ca627bf remain unfinished preserved WIP.

Optional replay/dossier/window tools are not required ordinary-play or engine-
upgrade gates. Their named suite is `pnpm test:optional-replay`; it covers the
postmortem replay/dossier/windows and loop/replay modules when intentionally
invoked with matching inputs. `mandos.stageRetirement` is false by default;
retained thresholds do not automatically retire normal characters. A targeted bug may use a bounded trace or diagnostic replay when
it is necessary and inputs exist. Reproducing historical outcomes requires the
original executable, content, configuration and accepted start inputs; seed,
endpoint/census equality or a record's Git hash alone does not prove full
trajectory identity. Missing provenance is unavailable, not justification for
patching the default engine or changing old assertions to manufacture parity.

Basic archive integrity (#20), stopped-life records (#47), and the basic evidence
part of mixed stall issue56 stay active correctness work. Park only56's advanced
replay/dossier expansion. Operational OAuth/backup issue52 stays a distinct owner
follow-up; no private action is authorized by a documentation change.

Future experiments may be pursued in better-borg-c or independent borg-rs only
through their own owner authorization. Do not move Mandos code/tasks, adopt native
save/timing semantics, poll Rust or dispatch a Rust worker automatically.

## Validation and issue state

Default validation checks supported functionality, basic evidence and retained
bug fixes. Explicit optional-tool suites have separate commands/profiles and
cannot make an experimental engine enhancement a default prerequisite. A change
to an optional component still needs honest relevant validation when authorized;
parking is not permission to hide a required gameplay regression or false skip.

[The open-issue audit](tasks/mandos-scope-181.md) is a **proposal** for parent
review. Existing `backlog` is sufficient for parked work; do not create a second
state taxonomy. Engine/port labels and own-bug history keep their existing
meaning. C milestones use ADOPTED coverage rather than per-source carried/fixed
mirrors. Tracking-superseded closure preserves old C bodies/code/proofs and is
not source resolution. Parent applies live issue changes; this documentation
migration changes none of them and performs no milestone adoption.

## Owner-authorized shared-fixture proof of concept (2026-11-08)

[Task217](https://github.com/diegoami/mandos/issues/217) authorizes a small
[decision-boundary interoperability POC](CROSS-ENGINE-FIXTURE-POC.md), using
actual native CBUG-0066 fixture observations and the existing TS selector.

never changes production source, the default plugin or C-adoption coverage.
This is a targeted regression/evidence tool, not strategy research or a new
cohort program. Before/after input equality and declared fix states precede
interpreting differences; a mismatch alone is not a port-bug declaration.
